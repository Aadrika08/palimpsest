## Findings, in severity order

### P1 — Actual L cannot claim a complete source attempt while required bespoke work remains downstream

Preflight `:41–44` places Q/L before F, R and Context, forbids a backedge, and calls L the disposition for the “complete source attempt.” Yet F must independently finalize and R must be prepared/frozen afterward; holder opens, authenticated decoding, repeated rechecks, teardown and any bespoke acceptance audit also consume CPU afterward. None is closed by a prior L. Moving those terms into a different record or adding another measuring wrapper does not supply their final endpoint. Current accounting explicitly includes administrator/watchdog/bespoke-reader tails and leaves both whole-operation CPU and its justified upper bound unknown (`docs/plans/memory-accounting-provider-option.md:9–20,83–108`).

**Required resolution for actual admission:** distinguish a precisely bounded closed source-production scope from later project work; give every later process/phase a place in a finite nonoverlapping accounting roster and obtain the final endpoints required by the current boundary. Do not describe a pre-F/R L as whole-operation completion. If complete final endpoints cannot be supplied under that boundary, actual admission waits for the user's separate boundary decision. This review neither designs an exempt provider nor exempts a holder/reader. No actual Q/L-shaped fixture or self-attesting finalizer is needed for 6a.1.

### P1 — Exact authored records and the evidence-root binding are missing; top-level authored admission keys are insufficient

Preflight `:72` fixes the authored admission's keys and false claims, but the referenced producer, raw-audit, numeric-conversion and retention-commit records only receive descriptions, not exact schemas/key sets/value types/path formulas. `:74` expressly requires root review of those validators before implementation. The inventory must equal a roster derived from those records, so implementing now would make the author silently choose the authority structure that the validator later accepts. The `root` argument is also not yet tied to an exact authored namespace contract: rejecting actual prefixes is not a complete role/location binding.

**Minimum missing authored contract, finite scope:** freeze exact schema/key-set and cross-record equality tables for the authored admission, producer registration, raw audit, numeric conversion, retention commit, owner/control metadata actually consumed, and the fixed profile/software-closure references. Identify which old numerical/SNP-container value validators are reused directly and which envelope validators must be new. For every consumed physical leaf, name its sole role, canonical root-relative path formula, byte cap, required/optional/empty status, defining record and equality checks. Fix root canonicalization/symlink policy, exclusive authored-root provenance, the source/raw/numeric/control subtree boundaries and expected directories. Specify how the admission descriptor is held without placing its own digest in its derived inventory; reject overlapping/conflicting roles except explicitly identical references to one physical file. No digest of a nonexistent output and no inventory accepted merely because a scan agrees with itself.

The current D validator proves only relative syntax/size/digest shape (`src/palimpsest/memory_transition_vnext.py:54–63`); it cannot establish these role locations. Old producer code demonstrates why the binding matters: exact development schema, distinct external controls, sole owner/SNP paths and raw-audit/SNP equality are separate checks (`scripts/memory_family_producer_v4.py:43–102`). Do not reuse that actual old receipt by renaming its schema or canonicalizing its UUID.

### P1 — Fresh canonical source creation is necessary, but its actual bootstrap and replay producer are not specified

The proposed J→owner/A→E→V/C→Q/L→F→R→Context ordering is acyclic if J's job reference remains prospective and neither Q/L nor R references later outputs (preflight `:35–46`). Fresh canonical UUIDs are the coherent choice for the accepted Context; current `Engine.build` rewrites even a supplied canonical ID to hex before `RunWriter` (`src/palimpsest/engine.py:379–388,414–418`), whereas Context requires hyphens (`src/palimpsest/memory_transition_vnext.py:49–51,78–80`). Source application/events must equal that Context ID (`scripts/memory_family_terminal_audit_vnext.py:124,147`).

The actual source-owner file, source-job schema, direct successor E/V/C validators, source/condition factory ownership and bootstrap call path are not frozen. Calling `Engine.__init__` with a prepared writer is not evidence that the validation/provenance/restore/bootstrap work of `build` was preserved (`src/palimpsest/engine.py:349–388`). Freeze the narrow factory factoring and source-owner/qualification file ownership before implementing that actual slice; preserve ordinary build/producer hex contracts and historical bytes. Authored canonical fixtures need no such actual factory.

The missing backend is substantive: V2 explicitly emits `actual_source_qualified=False`, provisional status and false lifetime/model/publication claims (`scripts/memory_family_source_seal_v2.py:27–51,274–305`); its reader cannot establish producer success or lifetime (`:505–512`). Actual replay must compare every positive source row and its source hidden endpoint through the genuine accepted policy, and every positive condition row through the successor wrapper (`scripts/memory_family_cell_replay_v4.py:51–121`). The existing public wrapper binds old receipt/source/runtime identities (`:157–209`), and the qualification loader gates before protected reads (`scripts/memory_condition_replay_admission_v1.py:52–57,240–269`). Neither a new flag nor an authored positive holder supplies that backend. Held-out admission cannot use a development label.

### P2 — One-condition leases are a sound initial software boundary; Context binding needs an explicit state contract

Preflight `:64–70` offers both a one-condition lease and a multi-condition slot map. Adopt the single nonoverlapping condition lease for 6a.1; leave the map out. Define whether opening yields an unbound source capability or an already bound Context, when `context` becomes available, whether rebinding the identical Context is idempotent, and that a different slot/Context is rejected and cannot mutate a live Engine's source view. Source fields must be derived from the held authored application/events/rows; bind the exact case/kind, source run, condition run, resources and schedule from the registered slot, with every Context hash checked. Context's syntactic validator alone cannot authenticate those facts (`src/palimpsest/memory_transition_vnext.py:66–93`); 3a independently checks source application/M/world/invariant hashes (`scripts/memory_family_terminal_audit_vnext.py:115–147`).

Keep one real fixed class, private sentinel constructor, owned ExitStack/FDs, active/poisoned/closed lifecycle, detached properties, teardown-error handling and a private authored domain. Public actual configuration must reject the authored domain. This gives later 3b/2b real authored FD provenance rather than caller-decoded dictionaries or a fake source class. It does not establish that an actual accepted holder exists.

Lease count is not owner count. Reopening an immutable source per condition need not start another source owner; conversely a warm per-case owner needs independently specified reset/SNP/RNG/controller/native invariants. Do not silently choose that owner topology while implementing a holder. `HeldReplayFiles.recheck()` rehashes every registered leaf (`scripts/memory_family_replay_custody_v4.py:156–187,267–279`), and proposed properties recheck before returning. Freeze call frequency and charge decode/hash/recheck/teardown CPU; no feasibility estimate follows from the lease design. The historical cold-start scenario in preflight `:133` is not a measured lower bound for this full project.

### P2 — Strong ancestor custody requires exact input/output topology, not only separate root names

`HeldReplayFiles` stores full directory identity, recursively from `/`, and rechecks every directory tuple and named edge (`scripts/memory_family_replay_custody_v4.py:31–33,129–154`); exact subtrees reject extra children (`:189–233`). Adding a file/directory under any held directory may poison the lease. `bound_payload` has intentionally different edge-only directory semantics (`scripts/memory_family_compact_v4.py:436–439,498–510`); substituting it to sidestep the strong contract is not a repair.

For 6a.1, freeze a small authored input tree and precreated output sibling branches outside the selected exact input subtrees; enumerate the ancestors held by every lease, including the root/registration's parent. Include explicit refusal cases for child/ancestor mutation, symlink/hardlink/replacement, byte mutation, expired lease and teardown failure. `HeldReplayFiles` derives expected directories from leaves and cannot by itself represent arbitrary reserved empty output directories (`:220–233`); count those separately in the namespace/census contract, without adding them to an exact input subtree as supposedly tolerated future writes. Authored tests cannot prove platform-wide ancestor stability. Actual launch/admission/log/atomic/quarantine/copy/teardown paths still need a static creation/mutation map before a real namespace can be admitted.
