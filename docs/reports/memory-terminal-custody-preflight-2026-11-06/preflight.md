## Freeze source identity before public adapters

Recommended UUID decision: a **fresh source epoch with canonical hyphen UUIDs from creation**, while preserving the V2 numerical layout (16 base arrays plus3 companion arrays). Original source inputs never get normalized, renamed, or relabeled. The current old source jobs/Engine/old schema validators are therefore ineligible for this epoch. The required new source-owner path and exact producer/codec envelope source closure must be separately specified and reviewed before actual admission. This report does not authorize that implementation.

The source owner must create the canonical ID before writer/manifest/events/SNP/owner/job/path creation. A successor internal Engine construction path must preserve that exact ID, while ordinary `Engine.build` continues its old hex behavior. Merely passing a hyphen ID to current `build` does not work. The same condition-owner construction issue must be resolved before2b integration is called usable. No public format boolean or caller-selected admission profile is proposed. Direct use of existing `Engine.__init__` could preserve a writer's canonical manifest ID (`engine.py:153`), but is not an approved factory: the asset/profile/native/controller/storage/restore/provenance bootstrap checks in `build` must remain enforced by a fixed successor factory. This preflight neither audited every bootstrap dependency nor established a qualified factory/backend; that exact source/serial Engine ownership is still a prerequisite.

A separately reviewed alternative is an explicit immutable identity-mapping record binding original hex IDs/paths/bytes to successor IDs at every adapter. That requires a deliberate Context/proof/schema amendment and preservation of both original and mapped identities; it cannot be smuggled into Task6 or represented as equality after string normalization. Recommendation is the fresh epoch because existing accepted Task1/3a contracts already require hyphens. Root must approve this choice and the source-owner file ownership. Without it, only authored canonical fixtures are possible.

## Concrete fixed holder and authored seam

One class only, `HeldSourceVnext`, in `scripts/memory_family_source_consumer_vnext.py`; no Protocol, duck type, injectable class, public constructor, callback supplier, loader override or boolean `qualified=True`.

Proposed API after root approves the epoch and ownership:

```text
open_source_numeric_vnext(root, registration:D, *, case_id, deadline)
    -> ContextManager[HeldSourceVnext]      # public actual gate before protected read
read_source_numeric_vnext(...) -> detached summary  # lifetime already closed
_open_authored_source_vnext(root, registration:D, *, case_id, deadline)
    -> ContextManager[HeldSourceVnext]      # private fixed authored schema, no actual grant
```

The holder's private constructor requires a module-private sentinel and the already built validating ExitStack, fixed internal admission domain (`authored` or `actual`), owned FD bindings, exact immutable role/namespace inventory, validated snapshot/application/source rows/events and base source identity. No caller can pass a check callback. Concrete checks are derived inside the module from its own fixed records/readers. Python privacy is an API/custody boundary, not hostile in-process code isolation.

`context` is a detached per-condition view built from the registered condition slot plus the authenticated base source; it is not caller JSON supplying source authority. Fix this semantic before coding: proposed `_bind_context_vnext(held, context)` validates every source identity/hash plus case/schedule/registered condition resources/run slot and records one immutable binding for that lease. If one holder spans multiple conditions, retain an explicit frozen slot map keyed by unique condition run ID and return detached views; do not mutate a single holder.context between Engines. Simpler recommended first implementation: one nonoverlapping holder lease per condition, reusing original source files but creating no new owner. Rechecking source bytes costs CPU and must be charged; this is not evidence of feasibility.

Read-only detached properties are `context,case,source_application,source_world,source_m,source_snapshot_reference`; add private decoded `source_events,source_rows,source_snapshot` for3b/5, with copies or immutable internal storage. Publicly exposing `/proc/self/fd` or a borrowed FD is unnecessary. `recheck()` validates deadline, active state, actual acceptance membership when domain actual, all registered FDs/bytes/edges, exact closed namespaces and bound Context identity; any failure permanently poisons this lease. Public properties require active lease, recheck before return, then deep copy. Read summaries have `lifetime_active=False` and cannot be passed back as held source.

## Ancestor churn and immutable-input separation

`HeldReplayFiles` does not just freeze the selected leaf. `_directory` at `:129–147` recursively opens every ancestor and records `_identity`, whose `:31–33` fields include size/mtime/ctime/nlink; `_check_dirs` at `:149–154` compares the complete tuple for every FD and named edge. Creating a child file changes parent mtime/ctime and may size; mkdir can also change nlink. Thus creating condition/control/output directories under an ancestor that a source/runtime holder already froze can poison custody despite unchanged source bytes. `exact_subtrees` also rejects any new child under an input subtree.

Do not resolve this by weakening old `_identity`, advancing its witnessed state without a reviewed mutation capability, or claiming sibling writes are always safe. `bound_payload`'s existing edge-only **directory** checks are distinct documented semantics, not permission to substitute weaker custody for a stronger qualification contract. Old case publication deliberately has a scoped mutation mechanism (`case_custody_v1.py:110–124,146ff`); it is tied to old rename/census and cannot be reused as copy permission.

Preferred topology: completed immutable original source/raw/numeric/control inputs plus frozen R/F/Q/L/namespace headers in an input subtree; a separate already existing output/control subtree for successor owner jobs/raw/stage/final/campaign. Keep actual original paths; this is a design for a fresh source epoch, not relocation of historical data. A separate root path is **insufficient by itself** if its shared ancestors change under a `HeldReplayFiles` lease. Before any lease, freeze exactly which directories all holders open (including runtime/source/assets roots and `/` ancestors), and precreate permitted shared output roots/case/owner directories so subsequent writes occur below nonheld sibling branches. Include all precreated directories, existing files, reserved slots and bytes in the initial census/storage/peak.

Do not yet assert precreation suffices: review actual owner/admission/log/atomic-marker/quarantine/fsync/teardown call paths for newly created child directories, the source holder's exact subtree choices, concurrent unrelated mutations of every absolute ancestor, qualification session holders, and all parent mutations during final copy. Frozen controls must not gain new children while held; publish later consumption/control records outside those frozen inputs and before opening the next lease. Source/consumption registrations cannot be amended after the holder opens. If these lifetime namespace invariants cannot be met on the admitted platform, actual backend remains unavailable. Authored tests should exercise real namespace mutations and demonstrate refusal, not patch stat/recheck.
