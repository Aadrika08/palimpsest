# CPU held-runtime preparation: source implementation

The CPU route now has explicit native-cache bindings, a data-only tmpfs copier
and a complete prospective import-profile candidate. Source commit
`884bb0a7a2e8c3b1ee6a835acf0538f5d12f6f3d` contains the implementation and authored
regressions. No installed tree has been staged, no held numerical qualification
has run, and all seven release gates remain open.

The [candidate](../plans/puck-cpu-observed-import-profile-candidate-01.json)
binds accepted CPU02 evidence and maps1,783 physical modules,38 exports,13 module
changes,11 prospective native-origin policies and two finite Cython cache rows.
Its340,908B SHA256 is
`d20076cd2e1961d1514bb135746b1701a14567136b80ee073fecedb389f929df`.
Mapping uses accepted inventory structure, not a fresh namespace/inode census.
The [creator/source evidence](puck-cpu-held-preparation-v1/source-evidence.md)
and [derivation program](puck-cpu-held-preparation-v1/derive-profile-01.py) explain
the exact predictions and separately rendered Torch helper. The final plan uses
four disjoint roots: SITE0, selected/usr1, selected/etc2, generated helper3.
The original29 host metadata entries span/usr and/etc; they cannot be represented
as one/usr/lib source root. The helper index was corrected before publication.

The explicitly versioned profile is accepted only by dependency-v3. It binds the
two plain cache modules to numpy.random.bit_generator/module_exec, proves absence
of physical alternatives before imports and permits first capture only in the
innermost declared initializer. Nested native/Python phases mask outer creators;
all names are screened before a phase pops. Existing metadata and references stay
bound; only declared new delegates may appear before creator close, after which
the exact dispatch-key set freezes. Terminal receipts require every declaration
sealed and closed with no open phase. Legacy export/profile rules remain intact.
This trusts authenticated initialization and observes persistent identities; it
does not isolate hostile in-process code or qualify native internals/transients.

The copier accepts authenticated registration data, fully censuses source package
roots, selects only declared system leaves, preserves empty directories/inert
bytes, streams bounded chunks and checks every destination leaf on tmpfs. It
rechecks source and destination hashes/namespace identities, returns dependency-v3
with fully censused package roots and closes every handle. It preserves failed
partial trees for its future parent. The caller still owns capacity admission,
hard termination, durable outcome publication and cleanup.

passes with the same guards. No full-suite pass or installed-stack pass is claimed.
The independent static review found missing terminal completion; the RED and
require_complete fix above address it. Final static review found no further
material source/profile compatibility issue.
