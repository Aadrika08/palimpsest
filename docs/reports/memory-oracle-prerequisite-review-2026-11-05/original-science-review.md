## Important finding

**P2 — Positional balance does not establish the required factor/order balance; disclose the exact new aliases before accepting this candidate schedule.** Candidate lines 33–35 propose left rotation by `row % 8` and correctly claim twice-per-position within each 16-row cost stratum. However `memory_decision_world.family_assignment` at lines 141–148 sets `hidden=row % 4`, `regime=RELATIONS[hidden & 1]`, and `relation_side=hidden >> 1`. For any fixed remaining condition and any fixed later position, the proposed rotation fixes `row % 8`, hence fixes both regime and relation side. This identical alias repeats in every stratum. Thus marginal positional balance cannot be presented as independent balance against registered factors.

For example, oracle at overall positions 2,3,4,5 in the south stratum receives respectively `(regime_bit, relation_side)=(1,1),(0,1),(1,0),(0,0)`, two families each; positions 6–9 repeat those four combinations. Each single oracle position has only one hidden-factor combination. Other remaining conditions have shifted versions of the same alias.

Why this matters: the approved completion plan line 15 asks for an outcome-blind balanced schedule verified against registered factors. The original study design lines 117–122 requires the factor table **and aliases** to be published, and does not infer independent factor identification from marginal balance. The candidate's instruction to recompute its twice-per-position assertion is insufficient by itself to close that gate. A condition-specific order effect that varies with the hidden factors cannot be ruled out by those counts. This is not evidence that such an effect occurs, that any primary estimate is empirically biased, or that full factor-by-position orthogonality is feasible/required.

Smallest resolution: explicitly document this alias and require independent prospective acceptance of its permitted interpretation, or replace the rotation with a separately reviewed fixed schedule that better controls the relevant aliases. Freeze one choice before development; do not use development outcomes to choose. Keep the deliberately own-first limitation explicit. No source/controller/family change or extra owner is needed merely to disclose and review this limitation.

A pure-stdlib arithmetic check, using only the declared 48 rows and literal schedule, confirmed all stratum/condition/position counts equal 2 and the aliases above. No repository module was imported. This is declared-roster arithmetic, **not actual launch-order proof**.

## Independently checked causal reasoning

1. **Existing initialization cannot implement the proposal unchanged.** `memory_decision.configure_selector:275–281` accepts only the unarmed acquired boundary; Engine additionally requires a clean paused boundary and preserves all state outside U/selector (`engine.py:1461–1478`). The existing oracle mapping demands prior admitted own gold and a fully configured resource/provenance (`memory_family_oracle_admission_v4.py:589–629`), and `_prior_own:548–574` requires a full `compact-pair-pass`. The pending lifecycle and new replay/admission identity are therefore necessary, not optional bookkeeping. Candidate lines 17–21 and 43 correctly preserve this boundary.

2. **An actual pre-selector instrumentation boundary exists in source, but is not a proof.** Engine advances the real world, records actual cue/gate/intervention evidence, rejects a failed mandatory intervention, refreshes sensing, records the symbolic packet, then calls `advance_memory` (`engine.py:836–852`). Inside `advance_memory`, an observed cue transition constructs the actual trigger before `selection_for_condition` (`memory_decision.py:373–386`). A narrow lifecycle can therefore bind actual world evidence plus the exact detected trigger and resolve before selection; it must not wait for route commitment or post-run proof. The exact hook/replay mechanism remains an adoption gate. A schedule tick or world `applied` flag alone is insufficient: `advance_world:467–482` changes that flag/cue before attempting gate closure and may subsequently reject it.

3. **Gold is an evaluator truth claim, not a learned prediction or steering signal.** The registered definition compares source's actually observed expectations to independently reconstructed pre/post occupancy and actual intervention (`memory-confirmatory-v3-design.md:77–84`). `gold_target_ids:151–164` selects previously observed facts consistent with before occupancy that changed afterward, conditional on the trigger. Candidate lines 13,17–21 preserve this direction. The future implementation must bind exact pre-trigger observed M/source evidence, actual before/after geometry, applied closure or genuine null no-closure, and the actual trigger; it must independently reproduce these inputs rather than trusting a producer's IDs. Keep the existing no-fresh-passage-before-decision and reached-event obligations where reached (`memory_family_oracle_admission_v4.py:768–817`). No own U, regime label, future schedule, extra donor or rescue owner can substitute for these facts.

4. **Pre-event noninterference is correctly an unfulfilled gate.** The current selector path consumes oracle IDs on detected cue transitions, not on ordinary pre-event ticks. That is a useful source fact, not a complete proof: state validation/resource hashing occurs throughout the path. The new pending state must be accepted without changing M, detector/requests/supervisor, sensor packets, native/model/RNG state or ordinary actions; evaluator reads must not perturb world/sensing/cache state. Pending must differ explicitly from resolved-empty. Other eight arms must have no runtime truth hook. Immutable post-resolution identity, duplicate/late/wrong-trigger rejection and replay of installation order all remain necessary. Candidate lines 17–21,41 already require these, so their absence as implemented code is not a defect in this design-only artifact.

5. **The revised oracle is not automatically the old oracle or an upper performance bound.** The same pure target-limit-one selector (`memory_experiment.py:330–376`) does not establish equality when evidence provenance/timing changes. Candidate line 23 appropriately rejects numerical-equivalence assumptions and requires changed comparator behavior to be named/frozen. Privileged stale-fact targeting does not entail optimal steering, goal success or dominance of own. Do not interpret it as such in later figures or conclusions.

6. **Natural terminals remain scientific outcomes in every arm.** Candidate lines 25–29 extend genuine independently reconstructed natural non-goals to all nine arms, including oracle, at 900 and require only reached obligations. This avoids recreating outcome selection through oracle event reachability. A real zero-row prefix is not a numerical replay success or observed gold; positive prefixes must replay all actual rows. Operational/acquisition/intervention/audit/custody failures stay unscored and phase-incomplete. This preserves the original distinction (`memory-family-analysis-v3.md:42–47,120–131`) while explicitly needing new prefix-slot schemas. It does not convert old prefix evidence into an old full pass.

7. **Controls require more than equal empty traces.** The old analyzer requires own/sham equality and exact all-nine no-event trace, goal, duration, path, score and outcome equality (`memory_family_analysis_v3.py:293–311`); the old analysis contract additionally requires upstream zero-selector/behavior evidence (`memory-family-analysis-v3.md:82–90`). Candidate line 29 preserves these and adds zero resolver use. For a natural no-event zero-prefix, actual terminal cause, counts and lineage must still be reconstructed independently. Equal empty trace hashes cannot close this control.

8. **Primary scientific target and inferential gates remain fixed in intent.** Family is still the independent analysis unit; its three kind contrasts are equally averaged, and families receive equal weights (`memory_family_analysis_v3.py:319–325`). The candidate preserves the 48 development plus separate 48 held-out families, 3 kinds, all 9 conditions, cap 900 and margins 90/45, and explicitly preserves every original precision/null/success-harm/no-event gate (line 39). The original contract's model-based independence/normality qualifications, Bonferroni intervals, zero-variance refusal, strict margins, fixed development precision screen and unpooled held-out sequencing must remain exact (`memory-family-analysis-v3.md:17–38,49–102`). This amendment changes matrix eligibility and the oracle intervention; unchanged threshold numbers alone do not prove unchanged primary populations/controller behavior. Candidate line 23 correctly recognizes that separate check.

9. **No partial-family escape is authorized.** Current analysis requires all 48 families and all 1,296 scored slots without unmet prerequisites (`memory_family_analysis_v3.py:240–247`). All-nine prefix support is the appropriate prospective route; excluding early own failures, requiring oracle success, selecting a different donor, replacements or eight-arm inference would change the scientific population. Candidate lines 7–9,27–29,39,43 reject those shortcuts. Until adoption the current Task 3 rule explicitly leaves oracle unattempted and the phase incomplete (`memory-case-cell-qualification-v2-design.md:79,114`).
