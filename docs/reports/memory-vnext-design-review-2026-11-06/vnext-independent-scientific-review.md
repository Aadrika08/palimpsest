## Findings requiring specification changes

### S1 — High: choose the exact memory cut used to derive gold

**References:** amendment `docs/plans/memory-family-vnext-oracle-order-amendment-design.md:17-23`; original `docs/plans/memory-confirmatory-v3-design.md:77-84`; `scripts/memory_family_oracle_admission_v4.py:781-784,811-817`; `src/palimpsest/memory_experiment.py:151-164`; `src/palimpsest/memory_decision.py:383-391`.

The old comparator derives gold from `task['m']`, the authenticated source memory, and actual event occupancy/trigger evidence. Exact source path: `_source_application` reads the source snapshot's `application` and validates `application['memory']` into `task` (`memory_family_oracle_admission_v4.py:442-476`); `admit_compact_pair` obtains that task at `:947-949`, passes it to `_condition_identity` at `:983-986`, and that function passes `task['m']` to `gold_target_ids` at `:813-814`. It does not use the post-event replay result as gold's memory argument. The proposed resolver says “authenticated observed memory expectations” without fixing whether these are immutable source expectations or the live oracle memory immediately before selection. These can disagree if an intervening observation changes status/evidence/estimate: `gold_target_ids` explicitly tests observed status, matching pre-event occupancy, and evidence timing. Applying the same function to different memory cuts is a different oracle, even with target limit one. Current full-path admission also refuses fresh passage evidence through decision; prefix-domain extension must not silently drop that requirement on a reached segment.

**Minimal fix:** define the resolver as an exact function of the authenticated acquired source M, exact case subject mapping, reconstructed actual pre/post occupancy, and the exact observed trigger; preserve the unchanged sorted-ID/limit-one selection rule and the reached no-fresh-passage invariant. Alternatively explicitly choose live pretrigger M, label the revised comparator accordingly, and freeze why this is scientifically wanted. Do not let the implementer choose between the two. State the expected valid target cardinality by kind and reached boundary, and which contradiction is an invariant failure. Keep unresolved gold distinct from resolved `[]`.

This is design clarification if source-M semantics are retained. Choosing a new live-memory comparator is a scientific definition change requiring prospective adoption, never a result-dependent choice.

### S2 — High: distinguish the executed world event from the detected cue trigger and specify every terminal cut

**References:** amendment `:18-21,27-29`; `src/palimpsest/memory_decision.py:275-291,357-390,400-408`; original `docs/plans/memory-confirmatory-v3-design.md:77-84,137-141`; V2 design `docs/plans/memory-case-cell-qualification-v2-design.md:65-79`.

“Actual eligible transition,” “first trigger selection,” and “no event” do not yet define one executable state machine. An applied world intervention, a sensed changed cue, and a detected trigger are distinct boundaries. The existing decision loop constructs the trigger and immediately invokes selection before applying passage observations in that packet. The new lifecycle must insert the evaluator at that exact logical cut without moving ordinary sensory/memory processing. A natural terminal may occur after world application but before a usable cue/trigger, or after trigger/selection but before commitment. Requiring nonexistent gold in the former would recreate the early-prefix exclusion; allowing unresolved resources at selection would change oracle behavior. Logging eventual timestamps alone cannot prove causal ordering.

**Minimal fix:** publish a bounded transition/terminal table with exact allowed inputs, mutations, audit records and failure classes. At minimum:

- Unarmed source: typed pending resource bound to this owner/source/case/resolver identity; no future gold.
- Armed before executed intervention: no evaluator read/use; unchanged policy inputs, RNG, ordinary memory and actions.
- World event applied but trigger not detected: retain actual intervention evidence; no selector; specify whether evaluation remains pending (recommended) or a separately typed nonbehavioral intermediate exists. A proved natural terminal here is 900, not missing future-gold infrastructure.
- Valid cue trigger detected: resolve against the specified input cut and authenticate it, then install exactly once, then call the unchanged selector in that same transition; no policy call, motor step, ordinary observation update or mutable alias may intervene. Null resolves to empty IDs using actual no-closure evidence.
- After selection: immutable resource, ordinary continuation and reached obligations. A subsequent unexpected trigger or installation needs a frozen rejection rule, not implicit reuse/re-resolution.
- Natural terminal without a trigger: no selection; unresolved gold remains unobserved. No-event kind requires zero resolver/selector use and the existing exact all-nine invariants. Resolver failure, malformed intervention, missing reached proof, duplicate/late install, or source/event mismatch is unscored invariant/infrastructure failure and stops the phase.

Define the narrow implementation seam and the independent replay/audit sequence that verifies it. Prove a noninterference projection excluding only declared evaluator metadata: source-to-pretrigger policy/motor inputs, M/E/detector/request/supervisor/command/native/RNG state and ordinary sensory processing must match the original no-use path. Bind installation to source/owner/event/trigger/input/output identities; reject a self-reported “installed before selection” flag without independently reproduced ordering. Preserve idempotent repeated-packet handling (`memory_decision.py:362-365`) without a second resolve. These are implementable design obligations, not a request for runtime evidence during this review.

### S3 — Medium: state the primary causal assumption after fixing own to first position

**References:** amendment `:23,33-37,41`; original analysis `docs/plans/memory-family-analysis-v3.md:17-24,42-58,106-118`; checker `scripts/memory_family_order_v4.py:127-177`; candidate `docs/reports/memory-v4-order-bounded-imbalance-candidate-2026-11-05.json:66-70`.

The amendment correctly discloses that own is always first and that public/higher-order balance is incomplete. It does not yet state the implication for the primary own-minus-no-U / own-minus-swapped causal interpretation. Every own observation is at position one; both references are later. No balance among those later eight positions separates an own-treatment effect from a first-position effect. Under exact reset and time-invariant deterministic behavior this need not bias simulated tick contrasts, but source isolation and elapsed-time stationarity are assumptions/proof obligations, not consequences of marginal factor counts. A prohibition on wall-time causal claims alone does not address position effects on ticks or terminal outcomes.

**Minimal fix:** retain the authorized own-first candidate and explicitly define inference as conditional on full snapshot/native/controller/RNG reset, immutable resources and deterministic control-tick semantics. If all inputs affecting the scored outcome are restored/isolated and wall time cannot enter simulated behavior, these mechanisms can justify position invariance without assuming an unmodeled wall-time treatment effect; that mechanism must be specified and independently qualified. Where external drift/resource effects can still influence outcomes, disclose the remaining stationarity/no-position-effect assumption rather than calling marginal balance its proof. State that treatment and first position are aliased and that the design does not identify their separate effects. Freeze diagnostic/receipt evidence without adding owners or outcomes-based exclusions, and publish the exact factor/position alias table. Do not fit a post hoc order adjustment or alter weights/precision gates. If the desired claim instead requires an order-robust treatment effect, that cannot be obtained under mandatory own-first using this matrix alone; it requires a separately approved order/design change. The conditional interpretation can be clarified without asking the user to choose an implementation detail.

## Scientifically sound parts and limits of this review

- **The donor problem is real.** `_prior_own` requires `compact-pair-pass` (`memory_family_oracle_admission_v4.py:548-574`), `_condition_mapping` requires its gold (`:589-611`), and the full identity path requires decision/event evidence (`:753-799`). An independently proved early own 900 does not satisfy that prerequisite. Merely moving own earlier cannot fix reachability. The old cyclic schedule can put oracle before own; the source-first/own-first amendment fixes temporal availability only.
- **An in-owner event-grounded oracle is not logically impossible.** Gold uses actual evidence before target selection, which is a causal implementation seam visible in `advance_memory`. It can avoid extra owners and future-world fabrication. It changes provenance/lifecycle and extends valid complete-matrix eligibility; action equivalence with the old comparator is conditional, not established here. Keeping old admission untouched and introducing a prospective version is correct.
- **Natural early failure must remain scientific data.** Genuine zero/positive prefixes can score 900 in every arm; an actual zero prefix has no neural replay claim. The V2 design's source-anchored terminal reconstruction and reached-obligation distinction are appropriate. A missing reached proof is not natural failure, and a missing *unreached* future decision cannot be used to discard one. Own/sham and no-event controls remain exact and must include terminal/outcome/path/count equality, not merely equal empty trace hashes.
- **The matrix and estimators remain fixed.** Each phase needs 48 families × 3 kinds × 9 scored conditions = 1,296 cells, plus the declared 144 source owners (1,440 study owners). The 48 development and separate 48 held-out families remain separate; paired kind values average equally within family and families equally within the three strata. No surviving-cell weights, replacements, retries, extra donor owners or eight-arm inference. The 900 cap, strict 90 benefit / 45 harm margins, two 97.5% primary intervals, null cost and own-only-failure guard, exact no-event control, finite nonzero variance and four development half-widths ≤45 remain unchanged (`memory-family-analysis-v3.md:42-102,120-131`). A legitimate all-zero-contrast dataset can still fail the nonzero-variance rule; the amendment does not guarantee that the fixed scientific goal will succeed.
- **The static checker has the right limited scope.** Its source recomputes six appearances per later position, two per stratum, hidden-factor 3/3 and public counts 2–4, and returns explicit limitations. Test text includes rejection of naive `row % 8` rotation (`tests/test_memory_family_order_v4.py:90-93`). Those are marginal constraints; they do not establish within-stratum hidden balance, interactions, wall-time balance, actual launch order, family independence or Gaussian interval validity. I inspected but did not execute the checker/tests or claim a fresh pass.
- **No impossibility proof follows for the full goal.** The current old donor protocol cannot admit a complete matrix on realizations with valid early donor failure; the proposed version can remove that logical dependency. Fixed precision, actual resource feasibility, authentic terminal evidence and all-nine invariants may still fail. Honest incomplete/infeasible disposition is required when they do; no fallback is authorized. The 12 CPU-hour memory lane inside 24 project hours and disabled raw deletion remain binding, including evaluator/audit overhead.

## Required comparator disclosure and prospective adoption boundary

Before implementation is an unambiguous specification, close S1/S2/S3 and enumerate exact versioned schemas, hook, independent replay boundary and clause-by-clause supersession map. In particular supersede the prospective study's old donor requirement and old order rule explicitly; do not silently change Task 3 engineering-pair authority or make its limited zero-prefix qualification a general continuation-model grant. No tests were run for this review.
