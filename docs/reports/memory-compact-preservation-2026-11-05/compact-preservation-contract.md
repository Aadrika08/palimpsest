## 1. What the current format actually stores

The active public compact profile is `docs/plans/memory-family-compact-evidence-v4-case-publication-v1-protocol.json`, not the superseded base/retained-condition profile. `scripts/memory_family_compact_v4.py:25–79,155–204,518–691,734–884` defines and validates these exact rows, 19,534 numeric/commitment bytes per completed tick:

| Retained row field | Exact dtype / per-row shape | Bytes | Preservation test while raw exists |
| --- | --- | ---: | --- |
| `encoded_input` | little-endian float32, `(4813,)` | 19,252 | dtype, shape and `tobytes()` equal |
| `sensors` | little-endian float32, `(4,)` | 16 | same, plus raw policy-event projection |
| `action`, `raw_output` | each little-endian float32, `(2,)` | 8 each | same; do not confuse mapped action with native control |
| `control` | little-endian float64, `(2,)` | 16 | exact applied-control recording bytes |
| `pose`, `next_pose` | each little-endian float64, `(3,)` | 24 each | exact recorded positions/headings |
| `reward`, `simulation_time` | each little-endian float64 scalar | 8 each | scalar dtype, shape and bytes, not decimal rounding |
| `eyes` | bool, `(2,)` | 2 | both true; masked recordings are ineligible |
| `revision` | little-endian int64 scalar | 8 | exact value and representation |
| Four `*_sha256` camera fields | each uint8 `(32,)` | 128 total | typed image digest for each camera at every row |
| `row_digest` | uint8 `(32,)` | 32 | exact typed legacy row commitment defined below |

`episode` and `tick` are reconstructed from the validated episode-zero contiguous chunk interval, not separate per-tick NPZ arrays. Chunk index/event ledgers must bind every tick exactly once in original order. NPZ uses `np.savez`, ZIP_STORED, an exact member set, no pickle/object arrays, exact endianness/shape, finite floating values and 32-row partitions (one final partial chunk permitted). There is no float quantization or compression-ratio credit. Array object identity and original raw NPZ container bytes are not preserved merely because numeric values are preserved. The comparison must use dtype/shape/raw-byte equality, including signed-zero bits, rather than `allclose`, rounded JSON or float equality alone. The existing production `_prove` uses this exact byte criterion for the eleven retained numeric/state fields.

### Cameras and omitted fields

Every raw row has four `uint8 (128,128,3)` cameras: effective `cam_left`, `cam_right` and unmasked `raw_cam_left`, `raw_cam_right`. Conversion requires both eyes true and the effective/raw pair to be identical. It stores four typed image SHA256 values at every row, but **does not retain all full camera arrays**. `audit-frames.npz` retains only paired RAW left/right pixels at the deterministic selected ticks; equality of effective/raw commitments lets those selected frames check both pairs. Maximum 16 selected ticks, two cameras each, 1,572,864 pixel bytes plus ticks/container overhead.

`audit_ticks` takes the union of six floor-indexed quantiles (denominator five), event/decision ±1 neighbors that actually exist, and the final two ticks, then returns them in trace order. Selection is fixed; there is no outcome-driven frame selection. A check must reproduce the union from the registered schedule and compare every selected pixel byte.

`latency` and `step_latency` are validated as finite float64 scalars then **dropped**. `population_stats` is validated as finite float64 2D data with trailing dimension four then **dropped**. No all-tick population/latency series is reconstructed by retained readers. Those omissions forbid claiming the compact bundle alone preserves runtime latency distributions, full neural population diagnostics or full-video/perception reanalysis. Required paper figures/claims using those quantities must keep separate raw evidence or an independently accepted explicitly sufficient derivative; no such derivative is established here.

The new `chunk-index.json` maps each compact chunk to the original event's sequence, legacy path, legacy SHA, episode/start/count/array schema, and its own compact SHA. This is a bijective index, not replacement of old raw chunk hashes with new hashes. `eyes_changed` is forbidden. Raw audit also rejects branch/controller replacement and replay events.

The retained source subtree keeps the original `worker-report.json`, owner record, raw-audit receipt, conversion inventory and final commit. ## 2. Digests: what remains recomputable and what becomes an attestation

For raw row `r_i`, let `H_i = state_digest(r_i without latency and step_latency)`. This typed digest includes dtype, shape, raw bytes and typed structure. It includes **full cameras and population_stats**; dropping population arrays does not remove them from this commitment. The compact row stores `bytes.fromhex(H_i)`.

The old trace formula is exactly:

`SHA256(H_0.encode("ascii") || H_1.encode("ascii") || ... )`.

The compact reader reconstructs it as `SHA256(stored_row_digest.hex().encode("ascii") || ...)`. It must NOT hash concatenated 32-byte row digests as the trace: that different formula is the separate `row_sequence_sha256`. `camera_sequence_sha256` hashes 32-byte typed camera digests in fixed row-major order `cam_left,cam_right,raw_cam_left,raw_cam_right`.

While raw is present, `memory_family_producer_v4._prove` independently checks all retained bytes, computes each raw row/image commitment, checks exact old trace/row/camera sequences against both compact manifest and raw-audit receipt, compares the copied manifest/events bytes, selected pixels and oracle pose projection. **The two equal `legacy_trace_digest` / `compact_trace_digest` strings in a receipt alone are not this proof.** The actual raw read and `_prove` are required under custody.
