## Required changes

### P1 — High: the pending oracle placeholder needs a legacy-rejected state marker

**Plan references:** `:57,84,88–90,95,99–101,212`.

The separate pending lifecycle and ordinary oracle `resource=[]` do not themselves make the placeholder inert. Existing `memory_task.validate_selector` accepts an empty oracle resource (`src/palimpsest/memory_task.py:162–185`), `selector_resources` returns it as gold (`:154–159`), and legacy `advance_memory` calls the selector without any pending-context check (`memory_decision.py:357–384`). If the separate Engine mode/context is absent or lost, the unchanged default path can therefore select with empty gold. A guard only in the new API cannot prevent this fallback. This would change oracle behavior silently rather than produce missing-evidence infrastructure refusal.

**Minimal fix:** choose and specify a narrowly versioned **condition-state marker/envelope that the old public `validate_state`/`advance_memory` reject**, with vnext context/lifecycle mismatch always refusing. The current old validator enforces exact version 3 and exact keys (`memory_decision.py:145–160`), so a versioned state/envelope provides a concrete existing refusal boundary. It need not be an arbitrary general config registry. Source acquisition/SNP remain the original v3; only an authenticated detached condition state is promoted at the unarmed fork, with an exact source-invariant projection excluding only declared selector/U plus new metadata. The ordinary oracle selector can still use syntactically empty resource internally while pending, provided only the fixed vnext path can consume that marked state and resolution precedes its one selection.

Before code, name ownership and interfaces for vnext state validation, configuration/arm, Engine step/default fallback refusal, state hashing/local witness reconstruction, and source-view comparison. Reuse one fixed validated worker without feeding vnext state through a fake old receipt or silently converting it to an ordinary accepted v3 state at a public boundary. Add authored negatives for removed mode/context/lifecycle, mismatched context, and direct old-API use of the promoted state; these must refuse before selection/policy, while genuine old v3 calls keep their behavior. This is a fail-closed representation clarification, not a new scientific comparator or user threshold decision.

### P2 — High: stage commitments and detached-result variants are not yet exact contracts

**Plan references:** `:50–62,66,84–90,100,106–110`.

`Stage` defines `input_sha256/output_sha256` as hashes of “exact typed inputs/output” but never specifies those canonical objects. Trigger construction consumes detector/packet identities; resolution consumes source M, event/occupancy and trigger; installation changes selector resource/provenance; selection consumes the ordinary live M and installed config. Different implementers can hash different projections while satisfying the current prose. That defeats independent reproduction and allows a binding to omit the very source/live-M or installation distinction being audited.

The frozen result has mutable nested dictionaries/lists and one lifecycle output, but the allowed variants and alias relationships are not exact. In particular a raised transition can have locally selected state while no Engine state/lifecycle is committed. The result must say which lifecycle it exposes, where the local selected lifecycle is reconstructed, and forbid a caller from treating it as committed after an exception. The prose intends this correctly; the serialized/API truth table is still missing. Likewise, a terminal witness after an earlier successful oracle trigger needs an explicit rule for `gold`/`selection` versus current-transition `stages`, rather than ambiguity over whether “oracle resolved” means now or earlier.

**Minimal fix:** freeze a small table of canonical preimage keys/types for every stage input/output and every transition-result variant: ordinary returned/unwitnessed, returned/witnessed, raised/witnessed, idempotent, and rejected infrastructure. Include the exact source-M versus live-M commitments, resource/provenance change and event identities. Specify the one source of committed versus local lifecycle and precise witness emission predicate/index update; reject contradictory combinations. Require detached result/witness/lifecycle projections with no mutable aliases to input/binding or to each other where later Engine assignment/mutation could alter an already hashed witness; a frozen dataclass alone is not recursive immutability. Authored tests should mutate nested result projections to prove isolation as well as testing unchanged inputs. These are bounded technical serialization choices and require no new user policy.

Freeze the import direction and class ownership; no dynamic source-loader override, fake public held source, or absent-class stub may count as integration. Add an authored integrated branch test through the approved fixed internal admission fixture seam once it exists, while retaining public refusal before real authority. The latter test need not run an actual owner. Do not claim Task 2 is production-integrated based only on helper write-order tests.

It does not change primary estimands, all-nine/48+48-family requirements or 900/90/45 and guard rules (`:16,148–151`). Metadata booleans are replay outputs, not caller permissions.

The plan correctly requires witness durability before assignment/rethrow, commit only after assignment, and infrastructure failure rather than rollback/900 when postassignment persistence fails. The writer's synchronous path actually flushes/fsyncs before returning (`records.py:213–234`). No extra policy/sensor/native call is needed.
