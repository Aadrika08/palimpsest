# Canonical bootstrap: recorder failure clarification

The frozen bootstrap contract preserves existing Engine.open cleanup behavior. Its requirement to check a failed manifest applies when the recorder can still persist that state. If a storage-budget or write error breaks the recorder, existing finish may itself raise, replace the body exception and leave a retained running/incomplete prefix. The implementation must not repair, rewrite around the byte cap, delete, retry or present that prefix as terminal success. The call must fail, retain the actual prefix and drain existing renderer/environment/writer cleanup paths as the current code permits. Actual future source qualification must reject every such incomplete prefix.

Cover the exact failure type/status and closure through the actual shared writer behavior and retained tests. This documents a discovered existing limitation, not a new cleanup policy or a native/source/backend qualification result. No additional full-suite rerun is required for report-only observations; if a test-only observation is added, rerun its covering node and label the earlier101-test full run as prior evidence. Source changes would require their own covering verification.
