## Namespace, cache and logs

Reuse Bubblewrap's private user/mount/PID/network namespace, disabled nested user
namespaces, dropped capabilities and read-only root. Mount only the trusted
Python prefix, accepted SITE and explicitly selected host files/aliases read-only;
the project/model/catalog paths are hidden. Supply a fresh64MiB kernel-sized
tmpfs scratch and a separate owned payload directory. A stdlib-only probe must
confirm changed network identity/no external routes, readonly SITE, hidden project
paths and a private empty cache prefix before the CPU imports.

The new worker request-v2/result-v3 preserves the legacy request-v1/result-v2
three-import route. Launch with `-I -S -B -X pycache_prefix=/scratch/pycache`;
validate that prefix is canonical, private, owned, empty and disjoint from SITE
and output. Exact CPython redirects normal source-cache lookups there. This
avoids the inherited cache without inventing bytecode mappings; arbitrary trusted
source manually interpreting data is not prohibited by this mechanism. The
parent also redirects project cache lookups before loading frozen helpers.

Use opt-in `log_mode='direct'`: exclusive held regular stdout/stderr files,
the existing process/RSS/disk/output monitor, synchronous leaf and directory
fsync/close. No pipe-drain/EOF/join thread is involved. The old default remains
unchanged. A watchdog covers worker/monitor teardown and synchronous log stalls;
a default-action kernel alarm covers the complete parent, including terminal
publication/transport. Late, failed or incomplete exits are failures.
