**Verdict: NO under the current contract; CONDITIONAL in principle under a prospectively reviewed successor.** A non-sampling label and false scientific flags alone do not make a new acquisition at `development/0/0/change` harmless to the required cohort. Nothing in this review authorizes a scope change or execution.

## What the current contract actually requires

- The fixed engineering tuple was selected before acquisition, but is explicitly **not automatically reusable** as a study observation (`docs/plans/memory-source-runtime-v2-implementation.md:19`). Its parent must validate both independently authorized namespace exports before native admission (`:53`).
- The current canonical coverage is unresolved and allocation unauthorized; arbitrary path descriptors cannot resolve it (`docs/plans/memory-source-preservation-v2.md:50–63`). `_coverage_contract` refuses unresolved coverage (`scripts/memory_family_allocation_v3.py:132–170`); the parent invokes it before runtime inputs and again before GO/lifetime admission (`scripts/qualify_memory_family_source_v2.py:382–443,481–490`). This is an actual admission dependency, not merely a report label.
- Future registration rejects historical run-ID and authored-ID collisions (`scripts/memory_family_producer_v3.py:316–325,438–449`). Case IDs include family and entity/evidence identities, not only a unique run UUID (`:181–203`). A fresh output directory or UUID therefore cannot repair exposing the same case/family now.
- Training/history/development/held-out disjointness and access logs remain mandatory (`docs/plans/memory-confirmatory-v3-design.md:195–200`). Analysis, family count and owner order must be frozen before development; observed results may not choose them (`:181–191`). The proposed oracle/order amendment also expressly forbids development-driven choice and is not adopted (`docs/plans/memory-family-vnext-oracle-order-amendment-design.md:3,41–45`).

## (a) Pure codec comparison of already-approved closed raw

**Yes in principle, with independent permission for those exact inputs and that bounded comparison.** Whether encoding/decoding preserves specified dtype/shape/bytes is a property of the retained input, codec and comparison. Prior training exposure cannot make equal bytes unequal. Requiring global scientific novelty solely to establish that narrow proposition would be an unnecessary logical prerequisite.

That does not authorize opening arbitrary historical raw, importing a model, replaying a cell, launching a native owner, or calling a public path whose existing admission requirements are unmet. An approved read-only comparison must bind the already closed input and candidate, preserve custody and originals, meter its work, state field omissions, and report only the actual comparison. Source raw and candidate equality is narrower than complete paper-evidence adequacy (`memory-source-preservation-v2.md:148–169`). Existing approved closed raw is a premise here, not a claim that such an eligible input has been found. Historical attempts do not acquire new scientific eligibility through this comparison.

## (b) New native acquisition at study case 0

**No now.** This creates a new observation and retained source lineage. Treating it as unrelated engineering history can make later V3 cohort registration reject family 0; dropping family 0 violates the fixed full cohort, and acquiring its source again violates the one-owner/no-retry intent. Merely setting `sampling_eligible=false` cannot prevent either consequence. Leaving later reuse undecided until after seeing acquisition results is retrospective selection.

A genuinely separate engineering contract could omit the *claim of global novelty* without lying about mechanical fidelity. To preserve a route to the mandated full cohort, however, it needs all of the following **before acquisition**:

1. **Explicit prospective adoption.** Independently review and authorize a versioned amendment identifying exactly which engineering namespace gate changes, while leaving canonical V3 coverage unresolved and its old acceptance rules intact. Freeze the scientific protocol/order/oracle choices relevant to using this case before its observations; the unresolved proposal cannot be selected or revised in response to this run. No patch, broad flag, self-issued GO or renamed old receipt can supply this authority.
2. **One reserved lineage, with later eligibility rules fixed now.** Register this exact tuple/case/seed and one source owner/run as the sole conditional source slot for the future development matrix, if reuse is intended. Freeze how its original raw/SNP/control lineage will be accepted, or refused, without a second acquisition. Later condition qualification must use the same source and its one closed own continuation; no substitute raw or extra owner (`memory-case-cell-qualification-v2-design.md:35–41,83–88`). This is a proposed change to registration/reuse semantics requiring review, not an existing entitlement.
3. **Honest exposure chronology and independent eventual coverage.** Preserve the new run in the exposure ledger. Define prospectively how a successor distinguishes this registered in-study prerequisite from genuinely prior/out-of-study history; never omit it from exports or pretend it predates no exposure. Eventually establish the independently authorized prior-history/training coverage and disjointness needed for scientific eligibility. A later-discovered prior collision or unverifiable coverage must refuse scientific reuse and leave the full phase incomplete. Neither this review nor an engineering GO can certify noncollision without evidence.
4. **Independent input and operational authority still required now.** Exact authorized model/runtime/source/input identities, permitted read boundaries, clean complete dependency closure, local no-replace/output custody, actual startup isolation, full lifetime supervision/accounting, reviewed resource feasibility, independent outcome review and exact-stage operator GO remain mandatory. Missing global novelty evidence is separable from these; missing authority to access an input is not. Do not inspect mixed held-out material to manufacture exports. The existing lifetime entry also remains independently closed (`memory-source-preservation-v2.md:218–243,283–285`).
5. **No scientific promotion by the engineering result.** Keep global coverage and all actual scientific/condition/study eligibility false; retain all raw and failures and charge the memory12h/project24h allocation. Reserve all original 48 development and separate 48 held-out families, three kinds, nine conditions, equal weights, original thresholds/guards and separate held-out GO. Preserve acquisition failures as unscored operational failures, not convenient 900 outcomes. The later same-raw numerical/condition qualification and all-nine requirements remain separate gates (`memory-case-cell-qualification-v2-design.md:65,79–88,110–114`).

This preserves the **full-cohort obligation**, not a promise that the cohort remains scientifically admissible. There is no evidence-free way to guarantee successful future completion if missing exports might reveal an earlier collision. If the requirement is to preserve current registration/reuse semantics unchanged, the answer for new acquisition is simply **wait for the exports and other gates**. A conditional successor is possible only by explicitly accepting and specifying the above prospective semantics; it must not be smuggled into a byte-preservation check.
