# Puck collection execution custody source unit

Continue the approved simulation goal and PR #116 with one read-only context,
`HeldCollectionExecution(custody_raw, expected_custody_sha256, deadline)`. Keep
historical loaders, protocol bytes and native owner denial unchanged. This unit
adds executable input custody and model materialization, not an owner grant.
No actual bundle, scene mint, registry, runtime binary or native owner is opened
by source tests. The public original-bundle positive remains unqualified.

The externally reviewed canonical custody manifest has exact version/kind,
owner ordinal, execution-freeze digest, seven descriptor roles, empty claims
and `executable:false`. Roles hold sources, admission (freeze/envelope), collection
projection, immutable model index, the selected original bundle, nine historical
producer sources and the exact runtime binary. All descriptors have fixed sizes
and hashes. Authenticate the manifest before opening roles. Bind source hashes
and source root to the pure collection envelope; derive before/after maps from
held files rather than accepting caller observations. Require the exact Python/XML
inventory under package/scripts/upstream, plus public protocol/index, pyproject
and lock entries. Bound discovery at 4,096 entries and 32 levels; hold discovered
directory edges, reject bytecode, symlinks and nonregular entries, and permit
regular non-code upstream documentation. The public context also checks that
the current imported package files come from the admitted source root and roster.
Only the four collection scenes may resolve. Fresh-worker loaded-code and external
runtime/dependency qualification remain later launcher requirements.

Use a stdlib holder with nofollow root/ancestor/leaf directory edges, regular
single-link files, stable identities and streamed hashes. At most 512 files per
role, 32 MiB per file, 64 MiB per role, 4 MiB per copied read; all role caps sum
to at most 80 MiB. Sources/historical files have 1 MiB caps, admission 1 MiB,
projection/index 64 KiB, report/protocol 4 MiB and checkpoint 1 MiB. The public
runtime descriptor uses the original exact 21,662,864-byte size and immutable
SHA. These are source input ceilings within existing owner resource limits;
actual execution cost remains unmeasured. Recheck on normal and exceptional close.

Admit the selected bundle through the unchanged fixed production provenance
facade. Construct the unchanged CPU model with `puck_model.make_model`, load
the admitted arrays strictly, set evaluation mode, and compare every live CPU
float32 parameter byte. Keep admitted arrays private. Model construction is
one-shot. Every staged interval uses this bound model with the existing
`stage_interval`; recheck inputs and parameters before and after it returns.
Any failed operation permanently poisons the context and closes its descriptors.
Returned metadata is defensive. Closed/expired contexts cannot act or close
successfully. A staged interval is not a native step or publication receipt.

Private generic lineage tests may use authored bundles and temporary files;
they must not override public pins or manufacture a public original positive.
Use actual unchanged Torch MLP construction/inference on authored parameters
in isolated subprocesses, plus file swaps, aliasing, missing/extra inputs,
deadline and parameter drift checks. Independently review the source unit.

Remaining admission includes supplied-original positive qualification, an exact
complete execution freeze, durable reservations, runtime/dependency observation,
bounded owner/stage supervision, lease/RSS/storage checks, native interval and
durable owner/collection close. This context does not make the existing envelope
executable or authorize protected collection. Preserve twelve owners times 600
intervals, 149 MiB recording/160 MiB owner, 3 GiB stage, 1 GiB RSS/free floor,
16 GiB retention and 2210/2260/2270-second stage limits. Physical rover and CI
remain excluded; all seven release gates stay open.
