This source-only addition validates one sealed condition after fixture raw
removal. It preserves the historical protocols and empty trust anchor. A new
explicit source profile binds the integrated checkout. It grants no pruning,
owner execution, study allocation or whole-case publication authority.

## Retained reader contract

`scripts/memory_family_retained_condition_v1.py` provides
`read_retained_sealed_condition(evidence_root, registration, *, case_id,
condition, condition_commit, deadline)`. The expected commit descriptor must come
from the externally registered/audited evidence chain. It is not derived from
the marker being checked. All portable paths retain the `cases/<case>/...`
form; this prospective reader operates on the unpublished `.pending/<case>`
tree, as the existing retained-source reader does. It refuses final aliases.

Admission reuses the sealer's registration and exact qualification-pin check
before source, snapshot or condition access. The qualification receipt is held
and its metadata checked, but no model, assets or numerical runtime is loaded.
The repository's trusted pin set remains empty, so normal unqualified calls
refuse. Authored test seams are not qualification evidence.

The reader holds the existing source and condition files, controls, histories,
snapshot, receipts and directory edges through validated teardown. It requires
raw absence (an empty `.raw` parent is allowed) and the exact sealed namespaces.
It reconstructs conversion inventory and support hashes from retained bytes,
checks the separate raw-audit receipt, reruns compact-pair semantics, and compares
the freshly derived pair receipt with the retained one. Oracle still requires
its bound prior-own receipt. No scientific ordering or seed binding changes.

The embedded cell-replay receipt is checked against its recorded trace, rows and
shared snapshot. It remains a historical attestation. Even self-consistent
hashes and a qualification pin cannot prove a fabricated execution happened;
the trusted external commit descriptor and audit provenance remain necessary.
Results say `raw_replay_performed=False`, `model_replay_performed=False` and
`replay_evidence='retained-attestation'`, with every existing claim unchanged.

No new per-case files or storage allowances are added. Existing row/chunk/file,
recording, support and control limits remain enforced. Read failure is read-only;
it does not delete or quarantine evidence. A later case publisher must hold
custody through its own authorized rename and durable close. A dictionary
returned by this reader is not a live custody or publication capability.

receipts/bytes, aliases, missing seals, raw residue and unexpected namespaces;
detect mutation during validation and preserve primary failures on teardown.
Run this route on project Btrfs and tmpfs, plus affected existing source checks.
Actual pruning, qualification, oracle ordering and whole-case close stay open.
