# Prospective q4 cache-guard contract

The in-place union candidate failed the authored dispatch counterexample. Keep
production and qualification descriptors q1–q3 unchanged. For the next source
unit, select an explicitly versioned q4 boundary-snapshot contract rather than
claiming an equivalent rewrite of arbitrary callback behavior.

This is an agent-owned engineering decision under the simulation goal. It does
not change study protocols, model thresholds, artistic or operator acceptance.
Nothing here implements q4, qualifies a runtime, creates actual 10 controls,
authorizes protected reads or revisits consumed attempts 01–09.

## Descriptor and source scope

Use nested `puck-held-runtime-import-qualification-v4` / `version: 4` under the
existing worker-registration-v3. Keep the descriptor field set, four CPU imports
and expected versions, main alias and nineteen negative imports. The CPU result
keeps result-v2 with explicit `qualification_version: 4`. Q1–q3 keep their tags,
results and code paths. Existing parent/auditor/observer epochs remain strict;
a later separate source epoch must explicitly admit q4.

Initial source scope is bootstrap, runtime qualification entry and authored tests.
The dependency registration builder is not the qualification descriptor builder;
do not introduce a dependency schema or change candidate D.

## New acceptance contract

Before existing lookups can dispatch on cache or allowance keys, require exact
builtin dictionaries for `sys.modules`
and source/dependency loaded maps, exact sets for source/dependency loading and
exports/aliases, and an exact frozenset for stdlib names. Every key/name must be
an exact string. Reject unsupported containers/keys without coercing them or
calling their hooks. Bind the initial stdlib-name baseline and refuse replacement
or widening. Check dependency maps only when a dependency receiver exists. Repeat shape/name
validation after the first reconciliation before taking the eligibility snapshot.

After first dependency reconciliation and alias validation, snapshot current
allowance contents and cache key-to-object identities. Use a single fresh builtin
whitelist for that guard. Eligibility is sampled at this boundary, not rebuilt
through callbacks for each key. Loading allowances never invent loaded-module
seals or permission for an unknown cache name.

Keep source/function/class dispatch checks, dependency reconciliation, held-file,
ancestor, image, process and environment checks, normal deadline, first-failure
identity, reverse close and permanent poison. Capture the second reconciliation's
export return. Add a q4-only late stability comparison after callback-capable guard
work and diagnostics: same cache/allowance receiver objects, supported types,
exact-string names, allowance contents, loaded/cache object identities and export
contents. First and second export sets may be different objects; their validated
contents must agree with captured state. An observed change or iteration failure
poisons the guard; do not retry with a new snapshot. Keep the final real deadline.

Bound cache names and the sum of allowance-entry counts to 65,536 each (count
duplicates in each input). Refuse excess before
larger snapshots; test the exact boundary and one-over case. These are new q4
limits, not retroactive q3 restrictions.

This is a sampling contract for trusted source/runtime operation. Exact types do
not prevent async mutation. Boundary comparisons cannot detect every ABA/remove-
and-restore event or mutation after the final observation. Do not claim atomic
cache validation, hostile-code isolation or full concurrent-lifetime enforcement.
Even legitimate observed mid-guard mutation may now refuse. Stronger guarantees
would be a separate requirement; do not grow a generic mutation framework.

## Finite implementation and proof

1. Test descriptor/result tags and old q1–q3 behavior first, including retained
   lying-membership, split-removal and reflected-union cases. Defaults and old
   outer epochs must not select q4 implicitly.
2. Test q4 supported inflight success, unknown-name refusal, unsupported types
   before hooks, same-size key/module/allowance swaps, container replacement,
   late second-export and diagnostic mutation, nested/publication behavior,
   alias/native/custody failure, first-exception identity, close and poison.
3. Implement only the explicit q4 branch. Independently review snapshot and late
   check placement, including the final deadline and optional diagnostics.
4. Only after semantics pass, adapt the existing real-worker 128/512/2048 workload
   to q4: three sequential samples of three light checks and a separately profiled
   keys-call count. Keep setup/cleanup outside timing. Record changed contract and
   exact source; compare with the retained original, without claiming equivalence
   or installed throughput.
5. Publish reviewed source/evidence. Stop if unknown-cache/seal/custody checks are
   lost, observed changes pass, old branches change or useful bounded reduction
   is not demonstrated. A larger runtime deadline and automatic actual run are
   outside this source unit.

The product exit remains a real public episode with recording, snapshots, replay
and exports, after separate runtime/operator/renderer qualification. All seven
release gates remain open.
