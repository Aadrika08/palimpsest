# Prospective memory-study amendment: oracle evidence and owner order

**Status: UNADOPTED proposed scientific design, not an implementation specification, accepted protocol or execution authority.** Source-only clarification on 6 November 2026 addresses scientific review findings S1–S3; exact successor schemas and exception-safe witnessing still require a separately reviewed implementation specification. No study, actual owner, protected case/catalog, raw recording, SNP or model was read/run to prepare it. No tests, model/dependency imports or services were run. Historical protocols, pins and the reviewed case/cell engineering authority remain unchanged. Raw deletion stays disabled, including after any future preservation pass.

## The scientific admission problem

Current V4 oracle admission requires a same-case prior-own full `compact-pair-pass`, including reached event/decision evidence (`memory_family_oracle_admission_v4._prior_own`, `_condition_mapping`, `_condition_identity`). An independently valid natural own failure before those boundaries can have score900 without furnishing that donor. Complete-family analysis nevertheless requires all1,296 cells and no unmet prerequisites. Honest early-prefix formatting alone cannot close this gap. This depends on donor-boundary reachability, not on own reaching the goal. No empirical incidence or universal reachability result is claimed.

The old analysis also rotates the nine-condition list: row1 schedules oracle before own (`memory_family_analysis_v3.condition_order`). The approved completion plan instead proposes source→own→remaining eight. That is a prospective order change requiring new order/analysis identities; it fixes temporal availability when a donor exists, but not the early-donor problem. Neither issue permits dropping/replacing families, an extra rescue owner, or inference from eight conditions.

## Proposed direction for independent scientific review

Remove the cross-owner donor dependency **only in a new prospective version**. Derive privileged target IDs from actual reached event evidence inside the already scheduled oracle owner, before that owner's first corresponding selector call. The oracle remains a target-selection comparator, never privileged steering. Other eight arms receive no evaluator truth or resource hook.

### Gold definition: immutable acquired source memory

Use exactly the authenticated acquired **source M**, not live oracle M, to compute gold. The old path obtains `task` from the source SNP application (`scripts/memory_family_oracle_admission_v4.py:442–476`), passes it through `_condition_identity`, and calls `gold_target_ids(task['m'], before_occupancy, after_occupancy, trigger)` (`:811–817`). The successor retains this argument cut: an immutable, independently source-bound copy of that same `task['m']`, exact case subject mapping, independently reconstructed **actually reached** before/after passage occupancy and the exact detector-produced trigger. The resolver must not consult own U, a regime label, future scheduled geometry, post-event replayed M or a mutable live-memory alias.

Keep `memory_experiment.gold_target_ids`'s observed-fact, matching prior occupancy and evidence-timing tests (`src/palimpsest/memory_experiment.py:151–164`), sorted-ID ordering and the unchanged selector limit one. At a valid reached trigger, change must yield exactly one target and null must yield resolved empty IDs, using actual unchanged passage occupancy for null. No-event must never resolve or select: its runtime gold remains **unresolved/unobserved**, distinct from the mathematical empty-gold convention. There is no invented resolved empty receipt for an unreached event or trigger. Contradictory cardinality, source observation/evidence, subject mapping, occupancy, applied intervention or trigger proof is an invariant/infrastructure failure, unscored and phase-stopping; it is not a natural 900.

This fixes only gold's memory argument: the ordinary `selection_for_condition` call still receives its original live-M argument and unchanged selection behavior. Do not substitute source M into ordinary live processing. The reached no-fresh-passage invariant and replay must establish the relationship; matching output IDs on examples is not a proof of comparator equivalence.

Preserve the reached **no-fresh-passage-through-decision** invariant (`memory_family_oracle_admission_v4.py:779–783`). Check every actually reached packet up to and including the decision boundary, including a terminal sensed packet if reached; any observed passage sample in that segment refuses. An early prefix does not claim later compliance. This prevents a prefix extension from silently substituting newly observed live facts for the source expectation or dropping a reached invariant.

### Bounded lifecycle and exact logical cut

An applied world change/intervention, its `memory_sensed` packet, a detector-produced cue trigger, selection and route commitment are distinct cuts. World changes precede sensing in `Engine._step` (`src/palimpsest/engine.py:838–855`). The current memory loop builds a trigger and immediately selects, then revises M and only afterward consumes that packet's passage observations (`src/palimpsest/memory_decision.py:373–391`). Insert the oracle-only evaluator at **that existing preselection cut**, after construction/validation of the actual trigger and before the existing `selection_for_condition` call. Do not move detector, cue, passage, request, supervisor, policy or motor processing. The other eight arms retain their existing path and receive no evaluator input or hook.

The table defines conceptual states and mandatory evidence, not serialized schema fields or permission to run an owner. Pending and resolved empty must be distinguishable in the eventual exact schema.

| Cut / lifecycle state | Allowed operation and mutation | Required independently reproducible evidence / refusal |
| --- | --- | --- |
| Authenticated unarmed fork: pending | Bind the exact source M/SNP/application, owner/run/case, ordinary history/U, resolver/source/runtime closure and frozen event schedule. No future target IDs. | Exact restore and declared substitution invariants; no pending resource presented as usable empty gold. Existing unarmed-only `configure_selector` is unchanged. |
| Armed, before world event: pending | Ordinary continuation only; no resolver read/use, resource install or oracle selector call. | Ordinary source-to-pretrigger state/input projection matches the original no-use path, excluding only declared evaluator metadata. An unexpected trigger refuses. |

No resource resolution solely because the schedule or world event occurred. | Independently reconstruct actual geometry/occupancy, intervention acceptance and sensed/detector progression. Missing **unreached** trigger/gold is not a failure. Malformed/rejected intervention is. |

This idempotence does not authorize resuming a failed owner or replaying an interrupted transaction. |

Resolution, installation and selection are one bounded logical sequence; there is no scientific stopping point between them. Bind their evidence to one actual transition and immutable closure. A timestamp or worker flag claiming “installed before selection” is insufficient. Unknown/repeated triggers are hard refusals except the existing identical-consumed-packet return above. No retries, general callback/resource registry, arbitrary armed reconfiguration or extra evaluator owner is introduced.

### Narrow hook and independent replay boundary

The prospective implementation seam is a versioned oracle-only preselection branch with a fixed pure resolver and a single-use installation rule. It receives only held source M/identity and authenticated reached-event inputs; it cannot mutate source M, ordinary live state, world, policy, controller tensors, commands or RNG. Installation changes only the declared evaluator resource/provenance in the successor lifecycle. Existing `configure_selector` remains unarmed-only; an explicitly versioned narrowly constrained installation path is required, not an exception or general armed setter.

Independent audit must authenticate the source application/M and all owner/case/resource/runtime identities; reconstruct actual world/intervention and occupancy from retained geometry; reconstruct ordinary sensed packets and detector trigger; replay the unchanged ordinary prefix; recompute gold at the exact cut; reproduce one install-before-selection and unchanged sorted-ID/limit-one selection; then reproduce all reached revisions/commitment/terminal evidence. Compare the noninterference projection through the pretrigger cut: policy/motor inputs and M/E/detector/requests/supervisor/commands/native/controller/RNG state, with only declared evaluator metadata excluded. No new normalization may conceal mismatched forks. Authenticating a receipt without this replay is not proof of order or noninterference.

Exception-safe evidence is required even if a later natural `CueUnavailable` prevents `advance_memory` from returning: the current Engine emits returned decision records only after successful return (`engine.py:851–855`). The successor must distinguish reached resolver/install/select activity and local uncommitted memory effects from actually committed returned state, retain the exact exception cursor/outcome and avoid inventing missing return events. The implementation specification must define that bounded witness/publication path and exact pure-replay exception boundary before coding; this document does not claim existing logs already suffice. Failed witness persistence/custody/ordering is incomplete infrastructure evidence, not an authenticated natural outcome. No extra motor row, owner or retry repairs it.

The amendment intentionally changes oracle evidence provenance/lifecycle and complete-matrix eligibility. It does not assert numerical equivalence with the old donor-initialized comparator. A review or later qualification that finds changed actions must describe/freeze the revised oracle comparator explicitly. The primary own-minus-no-U and own-minus-swapped targets are intended unchanged; their controller behavior, populations and equal weights must be checked independently, not assumed from unchanged threshold numbers.

## Natural terminals in every arm

Prospective prefix evidence must cover all nine arms. A genuine independently reconstructed natural non-goal before event/decision remains a scored900, including oracle; future schedules are unexecuted and only actually reached obligations are required. It need not create a nonexistent decision/gold/donor pass. A zero-motor terminal has no neural calls or fabricated rows/pixels and grants no per-row numerical replay claim. Positive prefixes replay every actual row.

Acquisition, runtime, custody, accounting, malformed intervention and audit failures remain unscored and make the phase incomplete. The amendment must not reclassify a legitimate natural failure to evade the900 rule or classify infrastructure failures as scientific900. Full reached-decision obligations stay mandatory when reached. No-event still requires actual zero resolver/selector behavior and exact all-nine trace/outcome equality; own/sham equality also stays mandatory.

| Terminal cut in an already acquired continuation | Required disposition and retained evidence |
| --- | --- |
| Before actual event; including zero/positive motor prefix | Independently proved allowed natural non-goal receives 900; resource remains pending, no resolver/selector. Keep actual prefix, source-boundary/final post-step pose and exact terminal proof. No future event/decision/gold required. |
| World event applied, before a valid detected trigger | Independently proved allowed natural non-goal receives 900 with actual event/intervention/sensing evidence; resource stays pending and gold unobserved. A scheduled event alone supplies no gold. Rejected/malformed reached intervention or missing reached proof is unscored infrastructure. |
| During resolve/install/select | No ordinary natural-terminal cut is introduced inside this sequence. Resolver, install, selection, witness or identity failure is unscored infrastructure and stops; no partially installed resource, manufactured task failure or continuation retry. |
| After selected trigger, before route commitment | Independently proved allowed natural non-goal receives 900 only with all reached trigger/resolver/install/selection and exception-safe evidence. Commitment stays unreached; do not fabricate it. |
| At/after reached commitment or ordinary normal terminal | Validate all reached decision/gold/geometry/no-fresh-passage/replay obligations. Goal costs actual completed continuation ticks; proved non-goal costs 900. No malformed full terminal falls through into a prefix variant. |
| No-event kind at any terminal | No resolver/selector invocation; runtime gold remains unresolved. Exact all-nine ordinary trace/outcome/count/path/invariant equality and own/sham equality still apply. A trigger contradicts the registered no-event domain and refuses. |
| Any cut with unknown exception, missing reached proof, acquisition/owner/custody/runtime/accounting/cleanup failure | Unscored, phase-stopping incomplete disposition; retain everything. A known exception name alone is not proof. Lack of a genuinely **unreached** future proof cannot be used to discard a proved natural failure. |

“Allowed natural” uses the frozen independently reconstructed terminal causes; the table invents none. Zero has count/path zero, no motor rows/pixels/neural calls and no positive numerical continuation qualification; positive prefixes retain/replay every actual row. Proof of natural 900 and technical qualification remain separate. Authored verification must cover all nine arms at each applicable cut, source-versus-live-M adversaries, pending versus resolved-empty, actual null occupancy, no-event non-use, identical-packet idempotence, unexpected/duplicate/late/wrong-event installation, exception-safe witnessing, pretrigger interference and ordinary reached-path equivalence. These are future acceptance obligations; no tests ran for this clarification.
