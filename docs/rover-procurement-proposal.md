## Electrical and control proposal requiring review

- **Bench supply → rated fuse/disconnect → deenergized-open relay contact → MDD3A → two motors.** Nominal motor rail 6V for the qualified bench; later Ni-MH option has its separately checked range. Driver maker specifies 4–16V and 3A continuous per channel, 5A peak. Adafruit specifies motor nominal 6V and approximately 0.2A stall, encoder 3–5V; these source ratings support selection headroom but do not replace received-part current/thermal tests. Do not sustain stall to verify a number.
- **Official USB-C supply → Pi; Pi USB A–B → Uno; Uno → driver logic, encoder and contact inputs.** Driver logic accepts 1.8–12V, so reviewed Uno 5V control is compatible. Keep motor and logic returns controlled; no Uno 5V signal enters Pi GPIO. MDD3A 5V/200mA output is not a Pi supply. CSI links feed two independent camera streams; configure/calibrate resolution, orientation, FOV, exposure and timestamp/skew before using an observation transform.
- **Independent stop:** proposed NC latching switch interrupts the relay-coil path without a Pi command; NO power contact drops when coil is deenergized. Uno must require explicit arm and locally expire an accepted command with its own clock, stop PWM and drop enable, reject stale/session/sequence/corrupt frames, and report acknowledgments. MCU watchdog/reset and pull-down defaults must return disabled. The relay needs a transistor/diode circuit; never drive the coil directly from GPIO. A single ordinary relay can weld and is not a certified safety system. Its release delay and actual wheel coast/brake behavior remain unknown. MDD3A onboard manual test buttons also need guarding against accidental motion.
- No final pins, timer allocation, PWM frequency, baud rate, expiry duration, speed limit, fuse value, battery cutoff or stopping distance is invented. Confirm encoder interrupt capacity, timer/USB interactions, coil/contacts under DC load and all component revisions in the M8 dossier. Physical fault testing covers host kill, frozen inference, USB loss, malformed/stale commands, Uno reset/hang, sensor loss, blocked wheel, stop-switch actuation, power instability and thermal throttling before enclosed floor use.

That smoke alone did not qualify full-host real-time performance, hour-long endurance or Pi performance. Laptop CUDA success does not transfer to Pi.
